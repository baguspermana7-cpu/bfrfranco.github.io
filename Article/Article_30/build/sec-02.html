Where he is right: the mechanism

The technical core of the video is correct. A language model produces one token at a time, it cannot reach the internet by itself, and an “agent” is a program that takes the model’s output, runs something, and hands the result back. An engineer who stopped reading here would have an accurate picture of the plumbing. The disagreements start with the words “did nothing”, which later sections test. This section sets down what is not in dispute, because everything after it depends on those points being solid.

2.1 Token by token

A model’s forward pass ends in a probability for each token in its vocabulary. The decoder chooses one, appends it to the context, and runs the whole pass again. The cycle repeats until a stop condition is met. Elder’s description (E1, 00:48–01:43) matches this exactly [S1]. Article 29, section on sampling, works through the logits, the softmax and the choice among the top candidates; none of that is repeated here. The point that matters for agents is the consequence: the same prompt can produce a different answer on the next run, and nothing inside the model guarantees that the output is correct, only that it is probable.

At inference the weights are fixed. A model does not learn from the conversation. Whatever it “remembers” within a session is the text sitting in its context window, and whatever it remembers across sessions is text that some other program stored and pasted back in. Elder’s “no memory” (E3) is accurate for weights and incomplete for the system, because agents add memory outside the model: files, databases, retrieved documents [S20].

2.2 The model never runs anything

Anthropic’s tool-use documentation says that Claude “returns a structured call that your application executes (client tools) or that Anthropic executes (server tools)”. The model signals this with stop_reason: "tool_use", and “your code executes the operation and sends back a tool_result” [S15]. OpenAI’s function-calling guide lists five steps: send a request with tools, receive a tool call, “execute code on the application side with input from the tool call”, send a second request with the tool output, then receive a final answer or further calls [S16]. The first model trained to choose which API to call, when, and with what arguments was described in 2023 [S17]. Two independent vendors and one research paper describe the same mechanism tool calling that Elder describes. He is right (E4) that a bare model cannot book a table: it emits text, and the harness around it does the booking.

The practical meaning for an operations team is a sentence worth keeping: every capability of an agent is a capability of the code that executes its tool calls. The permissions, network reach and blast radius of an agent are exactly those of the credentials its executor holds. The model has no other way to affect the world. Section 9 builds on this. The figure comparing the video’s account with the documented one appears in section 4, after the specific demo he uses has been examined.

2.3 No calculator, no encyclopaedia, no weight updates

Three further statements in the video are correct as stated for a bare model.

  • There is no calculator inside. Arithmetic is performed by learned circuits, not by an arithmetic unit; section 3 describes what those circuits look like and why they are not the same as a calculator [S4].
  • There is no lookup in a database at run time. Facts live in the weights, compressed and approximate, which is why a model can state a wrong fact in the same fluent register as a right one (Article 29).
  • Nothing is learned during the conversation. A correction given in turn five is available in turn six only because the text of turn five is re-sent.

These three limits are the reason the design rule at the end of section 3 reads the way it does. A system whose component can be fluent and wrong, cannot look anything up unless an executor does it, and cannot update itself, needs checks that live outside the component.

Operator takeaway

Read an agent’s tool list the way you read a contractor’s access request. The model proposes; the tools act. If a tool can write to the BMS, so can the agent, whatever the system prompt says. Permissions belong in the executor, where code enforces them, and not in the prompt, where text asks for them.
