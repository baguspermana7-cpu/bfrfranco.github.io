What an agent is: model, harness, tools

An agent is a loop. A program shows a language model the goal and the history, the model proposes the next action, ordinary code checks and executes it, the result is added to the history, and the cycle repeats until a stop condition. The model does the one thing a conventional program cannot do cheaply: turn untidy input (free text, logs, a screenshot, an error message) into a plausible next step without a rule written for that case. Everything else is conventional software.

Anthropic’s definition: agents “are typically just LLMs using tools based on environmental feedback in a loop” [S14]. The mechanism is not in dispute; the question is whether the three non-deterministic rows are worth anything. Plant-room analogy: in a PLC panel the I/O cards do all the switching, yet the control logic did not “do nothing”; it decides which output to drive and when. In an agent the model fills that role for inputs nobody wrote rules for. How reliably it does so is section 5.

4.2 The video’s restaurant example

Elder’s example of “the LLM did nothing” is OpenAI’s restaurant-booking demo, which he describes as probably a Python program calling probably the OpenTable API (E5, 03:50–05:11) [S1]. The demo came from Operator, a research preview announced on 2025-01-23, “powered by a Computer-Using Agent model, or CUA”, trained “to interact with the front-end of websites, meaning it doesn’t need to use developer-facing APIs”. The model “can use buttons, navigate menus, and fill out forms on a web page much like a human would”, and was “trained to ask for user confirmation before finalizing tasks with external side effects” [S58]. So the booking was not an API script: a vision model read screenshots of a web page and chose clicks (a computer-using agent). OpenTable as a named launch partner could not be confirmed; launch coverage lists DoorDash, eBay, Instacart, Priceline, StubHub and Uber [S58].

The example chosen to show the model contributes nothing is one where the model did the part a script cannot do: read an arbitrary page and decide what to do on it. The generic mechanism in his account (section 2) is correct; this example does not illustrate it.

4.4 Workflow or agent: six levels of autonomy

Anthropic: “Workflows are systems where LLMs and tools are orchestrated through predefined code paths. Agents… are systems where LLMs dynamically direct their own processes and tool usage” [S14]. In a workflow the model fills in steps inside a fixed skeleton. LangChain (July 2026) describes six levels: hand-written logic, a single LLM call, a chain, a router, a state machine, an autonomous agent, graded by three questions: who decides the output of each step, who decides which step comes next, and who decides what steps are available [S20].

Anthropic’s advice to builders agrees with the critic: look for “the simplest solution possible… This might mean not building agentic systems at all”, because agents bring “higher costs, and the potential for compounding errors”; it recommends extensive testing “in sandboxed environments, along with the appropriate guardrails” [S14]. An orchestrator that calls other models is another point on the same scale.

For the BMS team

Ask which of the three decisions the model makes: the output, the next step, the set of available steps. If only the output, it is a drafting tool inside a workflow, easier to test and bound. Each further decision given to the model needs its own deterministic check.

Two of the author’s counter-claims (C1–C6, graded in section 11) are tested here. C2, that the model acts as a semantic router or dynamic planner over unstructured intent: supported [S14] [S20] [S58]. C3, that observe, act and reflect (run tests, read the error, fix) is a genuine pattern: supported as a pattern, only partly as a new one, since ReAct dates from 2022 [S18] and closed-loop control is far older.
