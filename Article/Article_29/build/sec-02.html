Tokens: the unit everything is billed in

A model never sees letters or words. A tokenizer cuts the text into pieces from a fixed vocabulary and replaces each piece with an integer ID. Common English words are usually one token; rare words, other languages and source code split into several. Price, speed and context limits are all counted in tokens, so the tokenizer decides what a page of text costs.

2.1 What a tokenizer does

The dominant method is byte-pair encoding (BPE). Start from the 256 possible bytes. Count which adjacent pair of symbols is most frequent in a large corpus, merge that pair into a new symbol, and repeat until the vocabulary reaches a target size V. Encoding a new string replays those merges in order. “Byte-level” BPE, used by GPT-2 onward, tiktoken, Llama 3, Qwen and DeepSeek, can encode any string, because every string is bytes and no character is ever unknown [S72].

Two libraries recur. SentencePiece treats the input as a raw stream with whitespace written as ▁; it implements BPE and a unigram model and was used by Llama 1/2, T5 and Gemma (background, not re-read for this article). tiktoken is OpenAI’s fast BPE implementation, with encodings such as cl100k_base (GPT-4 era) and o200k_base (GPT-4o era and gpt-oss) [S72].

2.2 Vocabulary sizes

The vocabulary is a trade. A larger V packs more text into each token, so fewer steps are needed per document, but it enlarges the embedding table (V × d parameters) and the output layer. For Llama 3 70B that table is about 128,256 × 8,192 ≈ 1.05e9 parameters, with a similar output head, derived from the vocabulary in [S2].

Words split along morphemes the vocabulary has not learned. In o200k_base, “pendinginan” becomes pending|inan, “dikonsumsi” becomes dik|onsum|si, “megawatt” becomes meg|aw|att, while “Transformer” is a single token [S72]. Code is denser in symbols than prose: about 2.7–3.0 characters per token here, against 4.9 for English.

Tokenizers also change between model generations. Meta reports that Llama 3’s English compression rose from 3.17 to 3.94 characters per token over Llama 2 [S2]. Anthropic states that on its current tokenizer, 1M tokens is about 555k words, about 2.5M characters; that is 1,000,000 / 555,000 = 1.80 tokens per word, derived. Earlier Claude models fit about 750k words in 1M tokens, 1.33 tokens per word [S27]. So “a token is three quarters of a word” is a property of one tokenizer, not a law. The values quoted here span 1.19 to 1.80 tokens per English word.

2.4 Why tokens set cost and context

cost = input_tokens × input_price + output_tokens × output_price

Take a 10,000-word document priced at $2 per million input tokens (the Sonnet 5.5 list price [S27]):

  • English, o200k: 10,000 × 1.20 = 12,000 tokens, $0.024.
  • Indonesian, o200k: 10,000 × 1.60 = 16,000 tokens, $0.032.
  • Indonesian, cl100k or Qwen3: 10,000 × 2.05 = 20,500 tokens, $0.041.
  • English on the 1.80 tokens-per-word Claude tokenizer: 18,018 tokens by the dossier’s 555k-word rule, $0.036.

The same ratio applies to the context window. A window of 128K tokens holds fewer Indonesian words than English ones, in proportion to the table above. The effect compounds with the KV cache (section 4), which is also counted per token: a language that costs 1.5× the tokens also costs 1.5× the cache memory for the same document.

Operator takeaway

Capacity planning for a multilingual service has to use tokens measured on your own text and your own tokenizer. A vendor’s tokens-per-word figure for English will understate the load of an Indonesian-language workload by 19–51% on the tokenizers measured here [S72].
