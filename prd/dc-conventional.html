01 Purpose & problem

A conventional facility overview must reconcile electrical demand, cooling duty, environment, resilience and alarm state before routing a user to subsystem pages. Static marketing callouts cannot provide that trust; every primary result needs a denominator, source class and repeatable calculation.

Operational outcome

Expose abnormal state first, then the minimum site-level values needed to decide which subsystem to inspect.

Engineering outcome

Keep PUE, facility/IT load, CHW, WUE, carbon and fuel arithmetic on one immutable scenario and surface placeholders honestly.

03 Scope & non-goals

In scope

  • Facility alarm/quality summary.
  • Site power, cooling, water, carbon, environment, safety, network and fuel overview.
  • Locked CONV_MODEL and derived CONV_CALC.snapshot.
  • Seven subsystem navigation routes, KPI basis drawers, shared Design Studio, FAQ and theme.
  • The adopted four-hall campus: 10 MW IT design and 7.5 MW adopted load per hall, 500 racks/hall, 15 kW/rack current average, chilled-water CRAH thermal contract and design-point dPUE.
  • Tier-gated cockpit with separate public documentation.

Non-goals

  • No live BMS/EPMS/DCIM acquisition or control.
  • No configurable field setpoint editor.
  • No inferred off-design PUE or facility load beyond the adopted 30 MW operating point and declared 40 MW/58 MW design point without an approved part-load curve.
  • No stamped engineering, procurement, safety or regulatory conclusion.
  • No claim that static “Normal/Online” rows are measured values.
  • No claim that the adopted 30 MW campus scenario is installed, energized, commissioned or measured telemetry.

06 Formulas & derivations

Facility = IT × PUE = 30,000 × 1.45 = 43,500 kWNonIT = Facility − IT = 13,500 kWfacilityLoadKw(), nonItLoadKw(); Manual §03/06.
UPS loss = IT × (1/η − 1) = 30,000 × (1/0.96 − 1) = 1,250 kWNormal shared system output = IT / 2 = 15,000 kW/systemNormal module output = IT / 64 = 468.75 kW/moduleTwo independent 40,000 kW-rated systems, each built from 32 × 1,250 kW modules; snapshot.electrical.
ΔT = 27.0 − 19.4 = 7.6 KIT sensible-load reference = 30,000 / (4.186 × 7.6) = 943.0 L/sEvaporator duty = IT + UPS loss = 31,250 kWPlant-duty reference = 31,250 / (4.186 × 7.6) = 982.3 L/sTower rejection = 31,250 + 5,153.4 = 36,403.4 kWsnapshot.cooling; both flows are calculated references and measured header flow is unavailable. CHWS derives from 25.4°C rack inlet − 6.0 K assumed coil approach.
Water flow = WUE × IT / 60 = 1.20 × 30,000 / 60 = 600.0 L/minAnnual WUE definition expressed as steady-state equivalent cooling makeup; actual instantaneous tower demand varies.
Carbon rate = Facility × grid factor = 43,500 × 0.42 = 18,270 kgCO₂/hCUE_IT = grid factor × PUE = 0.42 × 1.45 = 0.609 kgCO₂/kWh ITDenominators remain explicit.
Usable fuel = 972,737 × 0.90 × 0.85 = 744,144 LBurn = 43,500 × 0.356384 = 15,503 L/h; autonomy = 744,144 / 15,503 = 48.0 hsnapshot.fuel; tank sizing and specific consumption are assumed engineering bases, not live curves.
Current IT = 4 halls × 7.5 MW IT/hall = 30 MW ITCurrent rack density = 7,500 kW/hall ÷ 500 racks/hall = 15 kW/rack averageDesign IT = 4 × 10 MW = 40 MW; design facility input = 40 MW × dPUE 1.45 = 58 MWThe governed four-hall geometry is adopted by CONV_CALC. The 40 MW/58 MW figures remain the 100% design point; the locked operating point is 30 MW/43.5 MW.

09 Non-functional requirements

Performance

  • First meaningful overview within 2.5 s on a mid-tier mobile CPU with local assets.
  • One-second clock and five-second rebind remain idempotent and leak-free.
  • Generated report opens within 1 s after snapshot capture.

Accessibility

  • WCAG 2.2 AA, 44 px mobile actions and visible amber focus.
  • Basis cards and dialogs have full keyboard path.
  • Units, source and state remain available beyond color.

Reliability

  • Missing snapshot becomes FAULT/unavailable, never a silently trusted fallback.
  • All calculations stay pure and deterministic.
  • Static/placeholder rows remain explicitly classified.

Security

  • Shared auth owns the tier decision; no secret in markup.
  • Docs remain public and carry no auth bypass.
  • No dashboard interaction sends a control command.
